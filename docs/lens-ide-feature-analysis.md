## Executive summary by domain

**Cluster connectivity.** Kubeconfig auto-scan (`~/.kube`), paste, file/folder sync. One-click cloud discovery for **EKS** (SSO / access keys / assume-role, all accounts+regions) and **AKS** (incl. private clusters, sovereign clouds) — both paid. **GKE manual only** (gcloud CLI path). Lens **creates** local kind + minikube clusters in-app (not just connect). Catalog + Hotbar (removed in the 6/7 redesign, restored April 2025), Contextual Tab Filtering, per-cluster HTTP proxy. Mandatory Lens ID sign-in since 5.5.2. Teamwork: Spaces with Owner/Admin/Member roles; transport is an in-cluster "BoreD" agent dialing out over WSS to a regional relay (EU/US), AES-256-GCM payloads, RSA-4096 key exchange, k8s impersonation for per-caller RBAC, no inbound ports, relay stores nothing.

**Resource browsing/editing (all free).** Full sidebar coverage: Nodes (shell/cordon/drain), all workload kinds, Config (incl. Leases, webhooks, PriorityClasses, RuntimeClasses), Network, Storage, Namespaces, Events (last 1,000), Access Control (RBAC objects), **CRDs auto-discovered with per-CRD submenus and editable instances**. Monaco YAML editing with schema validation, create-from-template, scale, rollout restart, CronJob suspend/trigger, column customization, namespace scoping.

**Pod tools.** Logs: multi-container, previous-container, scroll-back, jump-to-time, download. Shell/exec with container picker. Node Shell via privileged nsenter pod (no SSH). Port-forward with session-management view, persists across app restarts. Pod metrics/events tabs. **Native gaps (verified, open requests): no `kubectl cp` GUI, no attach, no ephemeral-container debug (3rd-party extension only), no force-delete, no shell selection.**

**Metrics.** Bundled one-click "Lens Metrics" Prometheus stack (free, still active 2026) or bring-your-own Prometheus. Node/pod/workload panels, history scrubbing + Event Overlay (2024). **No tracing, no log aggregation, no in-app Alertmanager UI** — firing alerts only via MCP tools (paid).

**Helm (free).** Charts browser across repos, README drawer, install wizard with Monaco values editor, releases table, values edit (computed vs user-supplied toggle), upgrade/rollback/uninstall, repo management in prefs, OCI registries (2025). All shellouts to a bundled helm binary against a per-cluster proxy kubeconfig.

**Terminal.** Smart Terminal: bundled kubectl auto-matched to cluster API version, auto context switch per tab, bundled Helm 3, binary dir/mirror prefs or BYO kubectl. `lens-k8s-proxy` (MIT) brokers API traffic. Lens CLI (`lens get-eks-token`, cluster connect/disconnect). Command palette.

**Security.** Security Center (Pro): Trivy Operator engine, continuous + spot scans, Images/Roles(RBAC-risk)/Resources(compliance) views, report export, air-gapped CVE DB import, external-scanner integration. **No SBOM, no admission/policy enforcement** (advisory only). Enterprise: SAML/OIDC SSO, SCIM, Control Center (org-wide feature toggles), full air-gap mode, offline activation. SOC 2 Type 1. Telemetry opt-out.

**AI (all paid).** Prism: NL queries running real kubectl + PromQL under caller's RBAC, right-click Summarize/Analyze, **BYO LLM (any OpenAI-compatible endpoint, incl. self-hosted/air-gapped)**. 2026.3: Prism Terminal Skill (executes real shell commands), MCP Server — read-only kubectl across all connected clusters + 6 Prometheus tools for external agents (Claude Code, Cursor, Copilot, ChatGPT). "Run your coding agent inside Lens" = the same MCP mechanism, marketing framing.

**Platform/pricing.** Personal free (<$10M revenue/funding eligibility; nearly the whole core IDE) / Pro ~$19.90/mo or $199/yr / Enterprise ~$99–99.90/mo. **Unresolved**: three conflicting Pro prices in circulation; a phantom "Plus" tier repeated across doc templates (likely stale snippet); a "Team" option on the live pricing page per GitHub #8271. Billing via Recurly. Paid-only: EKS/AKS one-click, Teamwork, Security Center, all AI, SSO/SCIM, air-gap, support chat. Date-based versioning since the 2024 relaunch. Extensions: React-based API, npm install (custom registry), curated list not a real marketplace. Win/mac/linux.

**OSS timeline.** Lens 6 relicense 2022 → source pulled early 2024, `lensapp/lens` unmaintained (not GitHub-archived) → OpenLens builds dead (v6.5.2, June 2023) → **Freelens is the active OSS fork** (v1.10.3 as of July 2026, ~5.3k stars, monthly releases, amd64+arm64). "Lens" vendor branding vs "Mirantis Inc." copyright still inconsistent in their own 2026 infra configs.

## Verified native gaps (things Lens does NOT do)

No `kubectl cp` GUI (#1369 open since 2020) · no attach (exec only) · no ephemeral-container debug natively · no force-delete pod · eviction-API-vs-direct-delete unclear (#5602) · no terminal shell selection · no SBOM export · no admission/policy enforcement · no tracing · no log aggregation · no in-app Alertmanager UI · no GitOps/deploy pipeline · no image builds · no webhooks/automation · GKE has no one-click discovery.

## Bearing on Komodo k8s support (see komodo-kubernetes-support-effort.md)

Lens's moat is four architectural things, not feature count: dynamic CRD discovery UI, per-user RBAC identity (kubeconfig-as-you + impersonation relay), pluggable metrics backend, and the AI/MCP layer. Komodo tier-2 "full parity" ≈ Lens's free-tier resource browsing minus CRDs/metrics — nothing from Lens's paid tiers. Complementary products: Lens has none of Komodo's git-driven sync, build→deploy pipeline, webhooks, scheduled procedures, or alerting.

## Cluster connectivity & catalog (22 entries)

- **Automatic kubeconfig detection (~/.kube)** [free/personal | GA] — Lens automatically scans and detects kubeconfig files in the default ~/.kube/ directory on startup; detected clusters appear under Navigator > Kubernetes Clusters > Local Kubeconfigs. ([source](https://docs.k8slens.dev/k8slens/getting-started/add-clusters/add-local-cluster/))
- **Add kubeconfig by pasting** [free/personal | GA] — Navigator > Kubernetes Clusters > Local Kubeconfigs > Add Kubeconfigs > 'Add kubeconfig by pasting' opens a modal where raw kubeconfig YAML can be pasted directly to add a cluster, without a file on disk. ([source](https://docs.k8slens.dev/k8slens/getting-started/add-clusters/))
- **Sync kubeconfig file(s) / folder(s)** [free/personal | GA] — The '+' button in Navigator offers 'Sync Kubeconfig file(s)', 'Sync Kubeconfig folder(s)', and 'Add from kubeconfig' to watch custom file/folder locations outside ~/.kube for kubeconfigs. ([source](https://docs.k8slens.dev/k8slens/getting-started/add-clusters/add-local-cluster/))
- **Manage Kubeconfigs (Preferences > Kubernetes)** [free/personal | GA] — A dedicated preferences page ('Manage Kubeconfigs', reachable by right-clicking Local Kubeconfigs > Manage Kubeconfigs) lists synced kubeconfig files/folders, lets you add from filesystem, configure the kubectl binary, and manage Helm chart repositories used across clusters. ([source](https://docs.k8slens.dev/k8slens/using-lens/preferences/))
- **One-Click AWS EKS Integration** [pro (docs also reference a 'Plus' plan) | GA] — Cloud auto-discovery for Amazon EKS: authenticates inside Lens (browser SSO dialog, IAM access keys, or an IAM role ARN) and then automatically discovers and lists every EKS cluster reachable across the user's AWS accounts/regions, connectable with one click — no AWS CLI or manual kubeconfig needed. ([source](https://docs.k8slens.dev/k8slens/getting-started/add-clusters/add-aws-eks/))
- **One-Click Azure AKS Integration** [pro (docs also reference a 'Plus' plan) | GA] — Cloud auto-discovery for Azure AKS: sign in with recommended settings (Azure Public) or advanced sign-in (choose cloud instance, org/tenant, for sovereign clouds or service-principal access). Discovered clusters are listed under Kubernetes Clusters > AKS, grouped by resource group across all accessible directories/subscriptions. Private AKS clusters are supported and connect via an Azure-managed network path rather than a public endpoint. ([source](https://docs.k8slens.dev/k8slens/getting-started/add-clusters/add-azure-aks/))
- **Add Google GKE clusters (manual, no one-click)** [free/personal (no paid gate found) | GA] — Unlike EKS/AKS, GKE has no cloud auto-discovery/one-click flow documented. Users must install gcloud SDK + kubectl, run `gcloud auth login`, `gcloud config set project`, and `gcloud container clusters get-credentials`, which writes the cluster into the local kubeconfig; Lens then picks it up via normal kubeconfig sync. ([source](https://docs.k8slens.dev/k8slens/getting-started/add-clusters/add-google-gke/))
- **Lens Catalog** [free/personal | GA] — A single index screen (opened from the second Hotbar-strip icon) of every item viewable in Lens: cluster connections, external website links, and in-app views like the Settings screen. Replaced the old pre-v5 'Workspaces' concept. Items are grouped into Categories, each listing entities of a registered group/kind (e.g. Kubernetes Clusters, Web Links); extensions can register custom categories (CatalogCategory class) and add/remove entities via addCatalogSource()/removeCatalogSource(). ([source](https://docs.k8slens.dev/k8slens/using-lens/))
- **Catalog item pinning to Hotbar** [free/personal | GA] — Any Catalog entity can be pinned to the Hotbar via its pin icon or the 'Add to Hotbar' action in its three-dot menu; clusters can also be added to the hotbar directly by right-clicking their icon in Navigator. ([source](https://docs.k8slens.dev/k8slens/using-lens/hotbar/))
- **Hotbar** [free/personal (one FAQ snippet called it a 'premium subscription feature' — conflicts with its placement in the general 'using-lens' docs section; unresolved, see notes) | GA (previously removed, restored April 2025)] — Left-side panel giving one-click access to pinned clusters/catalog items. Supports multiple 'banks' (columns of up to 12 sockets each), managed via the Command Palette (e.g. 'hotbar: create bank'). Was removed during a UI redesign around Lens 6/7 in favor of Navigator-only switching, then reinstated in the April 2025 desktop release ('Hotbar Returns') with tighter integration into tabbed navigation, Contextual Tab Filtering, and a context-aware Bottom Tray (terminals/logs/resources shown only for the active cluster). ([source](https://lenshq.io/blog/hotbar-is-back))
- **Workspaces (legacy, removed)** [n/a | removed] — Pre-Lens-5 concept for grouping clusters; fully removed and replaced by the Catalog (with categories/entities) starting in Lens v5. ([source](https://docs.k8slens.dev/k8slens/using-lens/))
- **Lens Teamwork / Team Spaces** [pro/enterprise (Personal/free plan lost all Teamwork/Spaces access as of Oct 1, 2024) | GA] — Cloud-backed collaboration layer: users create a 'Space', invite members by Lens ID, email, or shareable link, and share cluster access without exposing the raw Kubernetes API server or requiring a VPN. Space membership and per-cluster access are governed by RBAC roles configured in the Space. ([source](https://docs.k8slens.dev/k8slens/lens-teamwork/))
- **Add cluster to a Team Space** [pro/enterprise | GA] — Dedicated flow to attach a cluster to a Lens Teamwork Space, deploying an in-cluster agent so teammates can reach it through the Space instead of via a shared local kubeconfig. ([source](https://docs.k8slens.dev/k8slens/lens-teamwork/add-cluster/))
- **Remove cluster from a Team Space** [pro/enterprise | GA] — Right-click the cluster in Navigator > 'Remove from Space' unlinks it from the Space/Navigator, but the in-cluster relay agent (and its ClusterRoles/ClusterRoleBindings/namespaces/PriorityClasses) keeps running until manually deleted; the Remove dialog offers a 'Copy Command' kubectl snippet for that cleanup. ([source](https://docs.k8slens.dev/k8slens/lens-teamwork/add-cluster/))
- **Cluster Connect (relay protocol)** [pro/enterprise (part of Lens Teamwork) | GA] — The transport underlying Lens Teamwork's shared clusters. An in-cluster 'BoreD Agent' opens an outbound Secure WebSocket (WSS/TLS) connection to a 'BoreD Service' relay; the relay only proxies encrypted traffic (stores nothing) and the agent translates incoming requests to the caller's mapped Kubernetes RBAC user/group. Tunneled payloads use AES-256-GCM symmetric encryption; key exchange uses RSA-4096 (agent holds the private key, public key distributed to clients via the BoreD daemon). No inbound firewall ports are required on the cluster side. Admins pick a relay Region (EU or US) closest to the cluster at agent-install time, and traffic does not cross that regional boundary without explicit re-selection. ([source](https://docs.k8slens.dev/k8slens/lens-teamwork/cluster-connect/))
- **Lens Cloud data handling** [pro/enterprise | GA] — Documents what Lens Cloud infrastructure sees for Teamwork/Cluster Connect traffic: no payloads, credentials, or kubeconfig/config data are logged, persisted, or inspected by Lens Cloud; where a direct machine-to-API-server connection is possible, Lens Cloud infrastructure is bypassed entirely. ([source](https://docs.k8slens.dev/k8slens/lens-teamwork/lens-cloud/))
- **Roles and permissions (RBAC) in Lens Teamwork** [pro/enterprise | GA] — Per-Space and per-cluster role-based access control for Teamwork members, configured from a dedicated permissions/RBAC settings screen. ([source](https://docs.k8slens.dev/lens-teamwork/rbac/))
- **Cluster Settings page** [free/personal | GA] — Per-cluster settings screen (opened from the cluster's gear/settings icon) covering cluster display name, HTTP proxy server, and other per-cluster preferences. ([source](https://docs.k8slens.dev/k8slens/cluster/cluster-settings/))
- **Per-cluster HTTP proxy configuration** [free/personal | GA] — If a cluster's API server isn't directly reachable from the local machine, an HTTP proxy can be set in that cluster's Settings so the dashboard/terminal can still connect through it. ([source](https://docs.k8slens.dev/k8slens/cluster/cluster-settings/))
- **Multi-cluster management (Navigator + tabs + Contextual Tab Filtering)** [free/personal | GA] — Core multi-cluster UX: Navigator lists all connected clusters (local, cloud-discovered, Team Space); clusters can be opened in tabs/panels; 'Contextual Tab Filtering' and a context-aware Bottom Tray show only the terminals/logs/resources relevant to whichever cluster/tab is currently active, hiding unrelated ones, with no reload flicker when switching context. ([source](https://lenshq.io/blog/hotbar-is-back))
- **Lens ID** [free/personal (required for Teamwork features) | GA] — A single account/identity used to sign into Lens K8S IDE and other Lens cloud services (Teamwork, Cloud). Sign-up supports email/password, GitHub, or Google. Managed via the separate Lens ID Portal (change username/password, enable 2FA, connect third-party accounts, delete account). ([source](https://docs.k8slens.dev/k8slens/lens-id/lens-id-portal/))
- **SSO/SCIM for Lens Business ID** [enterprise | GA] — Enterprise admin capability to enable SAML- or OIDC-based Single Sign-On (and SCIM) for organization members' Lens ID accounts, toggled from an Authentication settings screen. ([source](https://docs.k8slens.dev/k8slens/lens-id/lens-business-id/integration-guides/))
